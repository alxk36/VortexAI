How traffic and the three agents fit together Architecture guide ↗

Application traffic

Client → Gateway → Load balancer → Application → Database / Storage. Responses return to the client. Identity permissions govern access to resources; identity calls are control-plane events, not another hop for every request.

Security feedback

Attacker → Synthetic actions → Cloud policy model → Event stream → Searcher findings → Builder recommendations → Admin approval → Updated policy → Attack replay.

What this lab models

Public storage exposure, repeated credential failures, and excessive service permissions. Searcher evaluates observed activity. Builder maps findings to explainable policy changes.

What comes next

Add isolated service containers and telemetry collectors, then replace agent rules with constrained AI decisions. This prototype is an in-memory model, not a VM, packet capture, or a production security tool.
